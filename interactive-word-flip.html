Visual Anatomy of the Kinetic Typography Engine

How the kinetic tokenizer and hardware-accelerated motion pipeline deconstructs typography into isolated GPU transform layers without destroying accessibility or causing document reflow.

Stage 01 DOM Serialization

String Tokenizer & Whitespace Keeper

The input string is split by space boundaries into discrete lexical tokens. To maintain precise typography layout, right margins (mr-[0.25em]) are applied dynamically to every word except the final token (last:mr-0).

// Word tokenization with margin preservation
const words = text.split(" ");
className: "inline-block mr-[0.25em] last:mr-0"
Stage 02 GPU Layer Isolation

Hardware-Accelerated Transform Matrix

Each word span is promoted to an independent hardware compositor layer via translateY or rotateX. Because geometry shifts avoid modifying top or height, zero CSS layout reflow occurs.

// Hidden to Visible state vector
hidden: { y: 20, opacity: 0 }
show: { y: 0, opacity: 1, type: "spring" }
Stage 03 Kinetic Damping

Spring Damping & Dynamic Width Morphing

Words ascend with calculated mass and damping physics (stiffness: 100, damping: 20). During 3D tumbler word switches, the container width seamlessly morphs to match the incoming word length, eliminating layout jumps.

// Physical Hooke's Law & Width Morph
transition: { stiffness: 100, damping: 20 }
tl.to(container, { width: nextWidth, duration: 0.45 })
Stage 04 Accessibility & A11y

Seamless A11y & Reduced-Motion

Breaking text into multiple DOM spans normally causes screen readers to pause after every word. The production component assigns the full sentence to aria-label and sets aria-hidden="true" on animated spans, while honoring prefers-reduced-motion.

// Screen reader & reduced-motion guard
<h1 aria-label={text}>
if (prefersReducedMotion) return <span>{text}</span>
